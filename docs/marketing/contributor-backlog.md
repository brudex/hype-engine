# Contributor backlog

Prepared for Day 3 of the 30-day contributor-growth plan. These are internal issue-ready opportunities; none has been published externally. They are intentionally bounded and can be developed and tested without production credentials.

| ID | Opportunity and evidence | Areas / likely files | Bounded scope and done when |
| --- | --- | --- | --- |
| CB-01 | **Make calendar post cards keyboard accessible.** Month and week calendar directives use clickable div cards for preview actions. | Frontend, accessibility; public/scripts/app/calendar-month-view.directive.js, calendar-week-view.directive.js | Use semantic controls or equivalent keyboard semantics; Enter/Space must open the existing preview; icon controls need names and visible focus. Preserve mouse behavior and verify with keyboard-only navigation. |
| CB-02 | **Give the date picker an accessible input contract.** The reusable date picker emits a readonly input with no explicit label or popup-state contract. | Frontend, accessibility; public/scripts/app/datepicker-input.directive.js, post editor templates | Support input ID, label/description wiring, and suitable ARIA state without changing the date model. Verify focus, Esc, and date selection with the bundled datepicker. |
| CB-03 | **Test scheduled-post job outcomes with fakes.** Three cron modules make critical status and batch transitions, but root tests cover only API contracts and release smoke checks. | Backend, testing; job-runner cron modules and helpers, new test files | Introduce only the seams needed for fake models/publishers. Test no due posts, all success, partial success, and total failure, including status, schedule status, and batch counters; npm test must make no network call. |
| CB-04 | **Add a provider adapter contract test harness.** The architecture calls for adapter-interface tests, yet the five provider adapters lack common root-level contract coverage. | Providers, testing; services/platform/index.js, service adapters, tests | Assert supported adapters expose testCredentials and publishPost, and incomplete fixtures yield safe structured failures. Mock HTTP, include the Instagram-to-Facebook alias, and never use real tokens. |
| CB-05 | **Implement Mastodon status publishing.** The Mastodon adapter validates credentials but returns a synthetic publication ID instead of creating a status. | Provider integration; services/platform/mastodon/service.js, adapter tests | Build status text from the selected post version and tags, call the statuses endpoint, return the provider ID, and normalize errors without logging authorization material. Verify with mocked HTTP only; media attachments are out of scope. |
| CB-06 | **Document a reproducible Docker success check.** The setup guide lists health URLs but lacks a short verification checklist for a first successful web, jobs, and migration run. | Docker, documentation; docs/development.md, optionally README.md or a safe script | Add exact expected health responses, a migration-status check, common symptoms, and safe cleanup guidance. Keep secrets out of commands and validate against compose.yaml and docker compose config --quiet. |
| CB-07 | **Add a development OAuth configuration matrix.** Supported providers have no single safe contributor reference for configuration and local test expectations. | Documentation, providers; new docs page, CONTRIBUTING.md, docs/architecture.md | List repository-defined field names, callback-origin prerequisites, safe local tests, and log redaction guidance for each provider. Link official docs; include neither secrets nor instructions to create provider apps. |
| CB-08 | **Cover flow validation and execution edge cases.** Server validation has entry-point, connection, and cycle rules not covered by the separate flow-builder unit tests. | Backend, testing; flow validation and executor services, tests | Add table-driven tests for malformed connections, duplicate IDs/names, entry points, side-channel nodes, cycles, and a valid minimum graph. Use mock node handlers to prove skipped branches do not run. Do not change semantics without a demonstrated defect. |
| CB-09 | **Harden external-media downloads against unsafe URLs.** The current controller is intentionally unimplemented and will accept a caller-controlled URL when built. | Backend, security; controllers/media.controller.js, focused helper/service, tests | Permit only HTTP(S); block private/local/link-local destinations after resolution; cap redirects and bytes; validate content type; use the media service. Test blocked addresses, redirects, and oversized/non-image responses with fakes and never log signed URLs. |
| CB-10 | **Surface useful job-server status to operators.** The architecture documents the jobs/status endpoint, while Compose health checks only health. | Backend, Docker; job-app.js, job-runner/index.js, docs/development.md, smoke tests | Return non-sensitive registered-job names and schedules while distinguishing readiness from execution. Do not change endpoint access policy or expose configuration, database details, or job payloads. Test the response shape and Compose config. |
