## DEV / Hashnode article draft — launch article

**Proposed title:** Why I open-sourced Hype Engine: a self-hosted publishing
and workflow automation project

**Audience:** developers who evaluate, self-host, or contribute to open-source
tools.

**Single action:** Run Hype Engine with Docker.

**Deck:** Hype Engine is an early open-source project for teams that want to
plan and automate social content while keeping the stack in their own hands.

**Draft body**

> Social publishing is not only a scheduling problem. Teams also need to
> organize accounts, content, recurring work, reporting, and the workflow
> decisions around publication. When those pieces are split among hosted tools,
> scripts, and manual handoffs, the automation becomes difficult to inspect and
> adapt.
>
> Hype Engine is my attempt to make that work more controllable. It is a
> self-hosted application for social publishing, scheduling, analytics, and
> visual workflow automation. The application runs with a web process, a
> separate background-job process, and PostgreSQL; the repository documents a
> Docker Compose path for local evaluation.
>
> The project is early, so this is not a claim of complete integration coverage
> or finished workflows. The useful next step is to let people inspect the
> tradeoffs, try the product, and help improve the interface, documentation,
> tests, Docker experience, provider adapters, and workflows in the open.
>
> Run Hype Engine locally with Docker:
> https://github.com/brudex/hype-engine#quick-start

motivation using the founder-reviewed narrative in `founder-story.md`. Link to
